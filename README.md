# 局域网提审 · 审核 · 交付工具

在同一局域网（同一个 Wi-Fi）里完成：**创作者提交作品 → 手机/笔记本浏览器审核评论 → 修改再提交 → 审核通过 → 正式交付到接收电脑**。

- 不依赖公网、不需要注册任何账号、没有任何付费服务
- 普通用户全程图形界面操作，不需要懂编程
- 创作者电脑运行「主服务」，接收电脑运行「接收端」，手机只用浏览器

## 2. 启动方法

### 创作者电脑（主服务，Windows）
1. 双击 `启动创作者主机.bat`
2. 浏览器自动打开创作者页面（http://localhost:8600）
3. 第一次使用，页面会引导你选择**工作区文件夹**，以后所有项目都放在里面
4. 使用时保持黑色命令行窗口开着，关掉窗口服务就停止

### 接收电脑（笔记本，Windows）
1. 把整个 `receiver` 文件夹（或直接拷整个项目目录）复制到这台电脑
2. 双击 `启动接收端.bat`
3. 浏览器自动打开接收页面（http://localhost:8700），页面上会显示本机地址（如 `192.168.x.x:8700`）和保存位置

### 手机（审核用）
不需要装任何东西，用浏览器参与审核（见下面使用说明第 3 步）。

> macOS 用户：双击对应 `.command` 文件（首次可能需要在「系统设置 → 隐私与安全性」里允许打开）。

## 3. 用户使用说明

### 创作者（在主服务电脑上操作）

1. **选工作区**：首次启动后点「选择工作区文件夹」，在弹窗里逐层点开文件夹，点「就选这个文件夹」。系统会记住，之后随时可以查看、打开或更换。
2. **建项目**：填写日期、品牌、项目名称，点「创建项目」。页面会显示项目保存在哪里。如果同名文件夹已存在，会让你明确选择「打开已有项目」或「取消改名字」，不会静默覆盖。也可以在工作区里直接放文件夹，用「切换/选择已有项目」继续工作。
3. **放待审文件**：把文件拖进页面虚线框上传，或点「打开项目文件夹」用资源管理器复制进去，然后刷新列表。勾选本次要审核的文件（视频、图片、文案、PDF、表格、PPT 都可以）。
4. **连接审核设备**：
   - 手机/笔记本与这台电脑连**同一个 Wi-Fi**；
   - 在设备上用浏览器扫页面上的二维码，或手动打开页面显示的地址；
   - 设备上输入名字和页面上的 **6 位配对码**，点「请求连接」；
   - 创作者页面出现该设备，点「**授权**」，设备自动进入审核页面。
5. **提交审核**：勾选要提交给的审核设备，点「提交为新版本」。生成 V01——这是当时文件的**准确快照**，之后你再改工作区文件，V01 不会变。审核阶段文件仍只存在你的电脑上，不会进入任何接收目录。
6. **看反馈**：「版本与反馈」里展开版本，能看到每个文件的审核状态（未审/需要修改/已通过）和每条评论，视频评论带时间码。
7. **修改再提审**：按意见修改工作区里的文件，勾选后再次「提交为新版本」生成 V02。旧版本、旧评论、旧审核结果全部保留，页面明确标注「当前版本 / 历史版本」。
8. **正式交付**：某个版本的**全部文件**都被标记「审核通过」后，该版本出现「正式交付」按钮。选择一台**在线**的接收电脑，确认后开始传输，页面实时显示进度。成功后两端都会显示结果、保存位置和交付记录；失败会写明原因，可在「交付记录」里点「重新交付」。

### 审核者（手机或笔记本浏览器）

1. 打开创作者页面上的地址（或扫码），输入名字 + 配对码，等创作者授权。
2. 「审核任务」里看到分配给自己的版本（标注当前/历史版本）。
3. 点版本 → 点文件，即可**直接预览**：图片、视频、音频、PDF、文本都能打开；视频可拖动进度条。
4. 视频审核：播放到某处暂停 → 在评论框写意见 → 点「⏱ 在视频当前位置添加评论」。评论会带时间码，任何人点评论里的时间码按钮，视频自动跳回那个位置。
5. 无法预览的类型（如表格、PPT）：显示文件信息，已授权的审核者可以下载后用本机软件打开。
6. 每个文件底部可标记「**✗ 需要修改**」或「**✓ 审核通过**」，结果实时回到创作者页面。

### 接收方（接收电脑）

1. 启动「接收端」后保持页面开着。
2. 第一次配对：创作者在他的页面点「添加接收电脑」输入你的地址 → 你的接收页面会弹出一个 **4 位确认码** → 告诉创作者（或他走过来自己看）→ 配对完成。
3. 页面上可以改文件保存位置（下载/桌面/文稿，推荐默认）。
4. 交付到来时页面实时显示接收进度，完成后显示保存位置和历史交付记录。

## 4. 已实现功能列表

- ✅ 工作区图形化选择、记忆、查看、打开、更换
- ✅ 项目创建（日期+品牌+名称）、同名冲突显式处理、已有文件夹接管
- ✅ 文件拖放/选择上传、项目文件夹浏览、勾选待审文件（显示类型/大小/所属版本预览）
- ✅ 手机/笔记本扫码或输码配对、创作者授权/拒绝/取消授权、配对码定时过期可刷新
- ✅ 接收电脑三步配对（填地址 → 对方屏幕确认码 → 完成），在线状态每 5 秒探测，显示保存位置与剩余空间，离线显示原因与「重新连接」
- ✅ 版本快照（V01、V02…）不可变：提交即复制+SHA256，工作区后续修改不影响
- ✅ 提审与交付严格分离：审核阶段文件不离开创作者电脑
- ✅ 审核端预览：图片、视频（含 Range 拖动）、音频、PDF、文本；其他类型显示信息并可授权下载
- ✅ 文件评论、视频时间码评论（点击跳回对应位置）
- ✅ 逐文件标记「需要修改 / 审核通过」，实时回传创作者页面
- ✅ 历史版本与评论永久保留，明确区分当前/历史版本
- ✅ 正式交付门槛：仅「全部文件审核通过」的版本可交付；交付前再次校验快照哈希
- ✅ 交付实时进度、接收端逐文件 SHA256 校验、存储空间检查、失败原因展示与「重新交付」恢复入口
- ✅ 两端交付记录、重启后项目/版本/设备/评论/审核结果/交付记录全部保留
- ✅ 未授权设备无法查看任务或文件（401/403），路径穿越防护
- ✅ 程序重启时进行中的交付标记为失败并提示重新交付，绝不假装成功

## 5. 未实现功能列表（如实说明）

- ❌ 断点续传：交付中断后重新交付是**从头重传**，不是从断点继续（文件会覆盖重写，结果仍保证正确）
- ❌ Office 文件（docx/xlsx/pptx）在线渲染预览：目前显示信息+下载后查看，未集成在线 Office 渲染
- ❌ 多创作者电脑共用一台接收端的冲突仲裁（接收端支持配对多台创作者，但同时交付未做排队优化）
- ❌ HTTPS 加密：设计场景为可信局域网，传输为明文 HTTP（有配对码+令牌授权，但没有加密）
- ❌ 审核任务的到期提醒/消息推送（页面自动刷新能看到新版本，但没有系统级推送）
- ❌ Windows 免安装绿色单 exe 打包：目前需要电脑安装 Node.js 运行环境

## 6. 已知问题

- 创作者页面轮询刷新（3 秒）时若恰逢新设备请求配对会整页重绘，正在输入的文本框内容会丢失（影响小：配对请求不是常态）
- 超大文件（数 GB）上传通过浏览器 multipart 传输，速度受浏览器限制；建议大文件直接用资源管理器复制进项目文件夹，再刷新列表
- HEIC 图片在部分浏览器无法直接预览（归类为图片但浏览器本身不支持时会显示加载失败，可下载查看）
- 交付中若接收端突然断网，已写入的不完整临时文件会被清理，但已开始传输的大文件需要重传
- 审核页面在 iOS Safari 全屏播放视频时会跳转系统播放器，时间码评论功能需退出全屏后使用

# 测试记录

## 测试环境

- 系统：Windows 11（win32），Node.js v22.12.0
- 测试方式：**同一台电脑上运行主服务（8600）与接收端（8700），用脚本模拟「创作者 + 手机审核设备 + 笔记本接收端」三方完整交互**
- 测试时间：2026-07-18

## 测试方法

全部通过 `tests/` 下三个脚本自动执行（非手动点接口、非只测后端）：

1. `node tests/e2e.js` — 完整用户流程（47 项断言）
2. `node tests/negative.js` — 负面路径（8 项断言）
3. 重启主服务后 `node tests/verify-persistence.js` — 持久化（9 项断言）
4. 页面冒烟：4 个页面 HTTP 200 + 页面内嵌 JS 通过 `node --check` 语法校验（8 项）

## 覆盖的完整流程（与真实用户操作一一对应）

选择工作区 → 创建项目（含同名冲突 409 → 选择打开已有项目）→ 写入真实素材文件（PNG/MP4/TXT）→ 获取配对码 → 错误配对码被拒 → 手机加入 → 授权前 pending → 创作者授权 → 手机获得凭证 → 无凭证/假凭证访问被拒 → 提交 V01（含 SHA256）→ 手机看到任务 → **手机打开视频（200 + video/mp4 + 字节数一致 + Range 分段 206）**、打开文本、打开图片 → 无凭证开文件被拒 → 添加时间码评论（5.2s）与普通评论 → 标记「需要修改」→ 创作者看到评论与状态 → **未通过版本发起交付被拒** → 修改工作文件提交 V02 → **V01 评论/审核结果保留、V01 快照内容未被后续修改影响** → V02 全部文件审核通过 → 配对没有接收端时报可读错误 → 完整配对接收电脑（确认码）→ 接收端在线且可见保存位置/剩余空间 → 发起交付 → 轮询进度直到完成 → **接收到的每个文件与批准版本 SHA256 完全一致** → 接收端本地也有交付记录 → **提审阶段文件未提前进入接收目录** → 数据落盘 → 重启主服务 → 工作区记忆、项目、两个版本、评论、审核结果、设备授权、接收端配对、交付记录全部保留。

## 负面路径

- 已授权但未分配的设备访问该版本 → 403 ✅
- 未分配设备任务列表为空 ✅
- 取消授权后 token 立即失效 → 401 ✅
- 空文件列表 / 无审核设备提交 → 400 ✅
- 路径穿越（`../../etc/passwd`）→ 拦截 ✅
- **人为篡改版本快照文件后发起交付 → 主服务交付前校验发现哈希不一致，拒绝交付** ✅
- 配对不存在的接收端地址 → 返回「连不上接收端」可读错误 ✅

## 尚未跨设备验证的部分（如实声明）

以下均为**本机模拟**，未在真实多设备环境验证，不宣称为多设备交付完成：

1. **真实手机浏览器**（iOS Safari / Android Chrome）打开审核页、播放视频、添加时间码评论——仅验证了服务端对 Range/Content-Type 的支持与页面 JS 语法，未在真机操作。
2. **真实第二台电脑**作为接收端跨网段传输大文件——本机回环（localhost）传输已验证一致性，未测真实 Wi-Fi 下的速度、断网恢复。
3. 二维码用手机相机扫码进入——二维码内容由服务端真实生成（含局域网地址），未用真机扫描。
4. 多设备同时在线审核同一版本的并发表现。

建议首次实际使用时，按 README「用户使用说明」做一次三台设备的真实走查；如发现问题，重点核对两台电脑在同一 Wi-Fi、防火墙放行 8600/8700 端口。

# 开发说明

## 技术栈

- **后端**：Node.js（≥18，用到 `fs.statfs`）+ Express 4 + multer（上传）+ qrcode（配对二维码）
- **前端**：原生 HTML/CSS/JS，无构建步骤，无框架。三个页面各自独立：
  - `server/public/index.html` — 创作者主界面（桌面优先）
  - `server/public/join.html` — 设备配对页（移动端）
  - `server/public/review.html` — 审核页（移动端优先）
  - `receiver/public/index.html` — 接收端页面
- **存储**：JSON 文件原子写入（写临时文件后 rename），无数据库依赖

选择这套组合的原因：零构建、依赖可随项目打包（node_modules 直接交付）、用户不需要任何开发命令。

## 进程与端口

| 进程 | 端口 | 运行位置 | 作用 |
|---|---|---|---|
| `server/src/server.js` | 8600 | 创作者电脑 | 创作者页面、审核页面、配对、版本快照、评论、交付推送 |
| `receiver/src/receiver.js` | 8700 | 接收电脑 | 配对确认、收文件、哈希校验、交付记录 |

## 数据存储位置

- 应用配置（记住工作区）：`server/data/app-config.json`
- 业务数据（跟随工作区，换工作区即换数据）：`<工作区>/.提审系统数据/data.json`
- 版本快照（不可变）：`<工作区>/.提审系统数据/snapshots/<projectId>/<Vxx>/<原始相对路径>`
- 接收端配置与记录：`receiver/data/config.json`、`receiver/data/deliveries.json`
- 接收的文件：`<保存位置>/<项目文件夹>/<Vxx>/<原始相对路径>`

## 数据模型（data.json）

```js
{
  projects:   [{ id, date, brand, name, folder, createdAt }],
  versions:   [{ id, projectId, label, note, createdAt, assignees:[deviceId],
                 files:[{ id, relPath, name, size, kind, sha256 }] }],
  devices:    [{ id, name, role:'reviewer'|'receiver', token, approved,
                 addr, receiverToken, createdAt, lastSeen, lastUserAgent }],
  comments:   [{ id, versionId, fileId, deviceId, text, timecode, createdAt }],
  reviews:    [{ versionId, fileId, status:'changes'|'approved', deviceId, updatedAt }],
  deliveries: [{ id, projectId, versionId, receiverId, status, error, savedTo,
                 startedAt, finishedAt, projectFolder, versionLabel,
                 files:[{ relPath, size, sha256, status, error }] }]
}
```

版本整体状态为派生值（不落地）：全部文件 approved → `approved`（可交付）；任一 changes → `changes`；否则 `pending/reviewing`。

## 关键流程

### 审核设备配对（手机）
1. 创作者页面 `GET /api/pairing/code` 生成 6 位码（5 分钟过期）
2. 手机打开 `/join` → `POST /api/join {name, code}` → 生成未授权设备
3. 创作者 `POST /api/devices/:id/approve`
4. 手机轮询 `GET /api/join/status` 拿到 `token`，存入 localStorage
5. 之后所有 `/api/review/*` 请求带 `x-device-token` 头或 `?token=`（媒体标签只能带 query）

### 接收电脑配对
1. 创作者页面填接收端地址 → `POST /api/receivers/pair` → 主服务转发到接收端 `POST /api/pair/request`
2. 接收端页面显示 4 位确认码
3. 创作者输入确认码 → `POST /api/receivers/confirm` → 接收端返回长期 `token`
4. 主服务每 5 秒 `GET /api/status`（带 token）探测在线状态、保存位置、剩余空间

### 版本快照
`POST /api/versions`：展开所选目录 → 逐文件复制到 snapshots → 计算 SHA256 入库。快照只读，交付前再次校验哈希。

### 交付
`POST /api/deliveries`（仅 approved 版本）→ 校验快照完整 → 接收端 `POST /api/deliveries` 建档+空间检查 → 逐文件 `PUT /api/deliveries/:id/file?rel=&sha256=&size=`（流式，Content-Length）→ 接收端写临时文件、校验大小+SHA256、rename 落盘 → `POST .../finish` 返回保存位置。任何一步失败：交付记录标记 failed + 可读原因，页面提供「重新交付」。程序重启时所有 running 交付自动标记 failed。

## 安全设计（局域网场景）

- 审核 API 全部要求已授权设备 token；未分配版本 → 403
- 接收 API 全部要求配对 token
- 所有用户相对路径经 `safeJoin` 防穿越
- 配对码短时有效；取消授权立即失效
- 明文 HTTP：设计前提是可信局域网，见 README 未实现列表

## 主要 API 清单（主服务 8600）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /api/state | 创作者总览（工作区/项目/设备/交付） |
| GET/POST | /api/workspace | 查询/设置工作区 |
| GET | /api/fs/roots · /api/fs/browse | 图形化目录浏览 |
| POST | /api/projects · /api/projects/adopt | 建项目 / 接管已有文件夹 |
| GET | /api/projects/:id/files | 项目文件列表 |
| POST | /api/projects/:id/upload | 上传到项目文件夹 |
| GET/POST | /api/pairing/code · /api/pairing/refresh | 配对码 |
| POST | /api/join · GET /api/join/status | 设备加入/轮询授权 |
| GET/POST/DELETE | /api/devices[/:id/approve] | 设备管理 |
| POST | /api/receivers/pair · /api/receivers/confirm | 接收端配对 |
| POST | /api/versions · GET /api/versions/:id | 提交版本 / 版本详情+反馈 |
| GET | /api/review/tasks · /api/review/versions/:id | 审核端任务 |
| GET | /api/review/file/:v/:f · /api/review/download/:v/:f | 文件预览（Range）/下载 |
| POST | /api/review/comments · /api/review/mark | 评论 / 标记 |
| POST | /api/deliveries · GET /api/deliveries[/:id] · POST /api/deliveries/:id/retry | 交付 |

接收端 8700：`POST /api/pair/request|confirm`、`GET /api/status`、`POST /api/deliveries`、`PUT /api/deliveries/:id/file`、`POST /api/deliveries/:id/finish`、`GET /api/local/state`（本机页面）。

## 二次开发

```bash
cd server && npm install    # 仅当 node_modules 缺失时
node src/server.js          # 主服务
cd receiver && node src/receiver.js  # 接收端
node tests/e2e.js && node tests/negative.js  # 回归测试
```

注意：本仓库 node_modules 已随项目打包，正常运行不需要 npm install。
